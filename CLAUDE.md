# CLAUDE.md — Landing page progetto AIC / Fondazione di Sardegna

Questo file raccoglie specifiche, obiettivi e approccio tecnico per la realizzazione della
landing page one page dedicata al progetto interregionale finanziato da Fondazione di Sardegna.
Lingua del progetto e dei contenuti: **italiano**.

Nel modulo di richiesta la "pagina dedicata al progetto" è esplicitamente prevista tra le azioni di

elemento di **rendicontazione** verso la Fondazione.

### Problema affrontato
Neodiagnosticati celiaci con disorientamento, ansia da contaminazione e isolamento sociale;
scuole senza strumenti adeguati per gestire esigenze alimentari speciali (celiachia, allergie,
intolleranze, scelte etiche/religiose); scarsità di percorsi coordinati tra le quattro regioni.

### Obiettivi del progetto (da comunicare nella pagina)
- Educazione sanitaria su celiachia, allergie, intolleranze ed esigenze etiche/religiose; inclusione scolastica.
- Strumenti pratici per docenti, famiglie e studenti per ridurre errori e contaminazioni.
- Autonomia e sicurezza dei celiaci tramite supporto nutrizionale e corsi di cucina.
- Ridurre ansia e isolamento dei neodiagnosticati con Q&A e confronto con professionisti.
- Rete interregionale stabile (Sardegna, Piemonte, Sicilia, Calabria) e condivisione di buone pratiche.
- Attività online capillari, replicabili e sostenibili; basso impatto ambientale (meno spostamenti).

### Risultati attesi
- Maggiore inclusione scolastica e sicurezza nella ristorazione scolastica.
- Più autonomia nella gestione della dieta, meno errori.
- Meno isolamento nei neodiagnosticati.
- **Oltre 1.000 partecipanti** complessivi alle attività online.
- Rete interregionale stabile e replicabile.

### Destinatari
Diretti: celiaci neodiagnosticati (bambini, adolescenti, adulti), familiari e caregiver, docenti e
personale scolastico, persone con allergie/intolleranze/esigenze etiche o religiose, volontari AIC.
Indiretti: popolazione generale, comunità scolastica, operatori della ristorazione scolastica,
comunità regionale dei celiaci.

## 2. Obiettivo del sito

Landing page **one page**, istituzionale/vetrina, con finalità **esclusivamente informative e di
rendicontazione**. Deve:
1. presentare i progetti realizzati;
2. valorizzare la collaborazione tra le quattro associazioni;
3. rimandare ai siti ufficiali delle associazioni per approfondimenti e iscrizione agli eventi.

### Funzionalità incluse
- Navigazione one page (menu ad ancore, scroll fluido).
- Link esterni ai siti delle associazioni partner / pagine evento.
- Layout responsive mobile / tablet / desktop.

### Funzionalità ESCLUSE (non implementare)
Form contatti, blog/news, integrazioni social (feed, widget), area riservata, prenotazioni,
e-commerce. Le iscrizioni avvengono sempre sui siti delle singole AIC tramite link esterno.

## 6. Approccio tecnico

### Contesto
- Sito esistente (rilevato dall'HTML pubblico, 28/09/2026): **WordPress 7.1.2**, **Elementor 4.3.0 +
  Elementor Pro**, tema custom `AIC-territoriale-master`, plugin Ele Custom Skin, **WP Rocket** (cache e
  minificazione: svuotare la cache dopo le modifiche), **Complianz** (cookie banner), Burst Statistics.
- Probabilmente **non** sarà possibile caricare un template di pagina PHP custom nel tema: la strada
  principale è Elementor. Il template PHP resta un'opzione di riserva (vedi sotto).

### Strumenti disponibili in questo ambiente
- **MCP Elementor** (`elementor-claudio-antonucci`): creazione pagine, lettura struttura, gestione elementi,
  classi e variabili globali, anteprime e pubblicazione. Consente di costruire la pagina direttamente
  nell'editor del sito.
- Skill **novamira**: ispezione/gestione del sito WordPress (plugin, tema, WP-CLI, filesystem) se il sito è
  collegato tramite Novamira.
- Prima di operare sul sito, verificare **su quale sito** punta ciascuno strumento e chiedere conferma prima
  di pubblicare o modificare contenuti live.

### Strategia (in ordine di preferenza)
1. **Elementor nativo (principale)** — pagina costruita con Flexbox Container e widget standard
   (Heading, Text Editor, Image, Button, Icon List, eventuale Nav Menu/ancore), stili via classi/variabili
   globali (rosso AIC, grigi, spaziature) così che il cliente possa poi modificare i testi in autonomia.
   Template di pagina "Elementor Canvas" o "Full Width" a seconda di header/footer del sito da mantenere.
2. **Elementor + HTML/CSS custom** — per blocchi particolari (es. timeline, card progetti) usare widget HTML
   o CSS personalizzato della pagina, mantenendo il CSS con prefisso dedicato (es. `.aicfds-`) per non
   interferire con il tema.
3. **Template PHP nel child theme (riserva)** — solo se si ottiene accesso ai file del tema: file
   `page-progetto-fondazione.php` + CSS/JS enqueued. Da considerare se Elementor risultasse limitante.

### Prototipo nel repository (`docs/`, pubblicato con GitHub Pages)
- Prototipo statico in **`docs/`** (GitHub Pages: branch `main`, cartella `/docs`), usato per validare
  struttura, contenuti e grafica con il cliente prima di trasporlo in Elementor. Istruzioni in `README.md`.
- Nessun framework/build: `docs/index.html` + `assets/css/style.css` (token in `:root`) +
  `assets/js/main.js` (menu mobile, voce di menu attiva, badge "Svolto"/"In programma" calcolati dalla
  data in `data-date`, anno nel footer). Senza JS la pagina resta completa.
- Vincoli GitHub Pages: **solo percorsi relativi** (il sito vive in `/<repo>/`), `.nojekyll`, `404.html`.
- `<meta name="robots" content="noindex, nofollow">` e barra "Prototipo di lavoro": da togliere in produzione.
- Contenuti provvisori marcati con `<span class="tbc">…da confermare</span>` e blocchi `.placeholder`.
- Loghi: SVG convertiti dai PDF con PyMuPDF, colori riallineati ai valori ufficiali; le versioni negativo
  FdS non hanno lo sfondo nero incorporato.
- Nel passaggio a Elementor, i token del CSS diventano colori/tipografie globali del kit; le classi
  personalizzate vanno prefissate (es. `.aicfds-`) per non entrare in conflitto con il tema.

### Requisiti tecnici trasversali
- Breakpoint del prototipo: mobile ≤ 639 (≤ 359 per schermi molto stretti), tablet 640–991 (colonne laterali
  impilate con due colonne interne), 992–1199 (due colonne, spaziature ridotte), desktop ≥ 1200. In Elementor
  i breakpoint di default sono mobile ≤ 767 e tablet ≤ 1024: adattare di conseguenza.
- Interlinea tramite variabili CSS (`--lh-body` 1.55, `--lh-lead` 1.45, `--lh-heading` 1.1, `--lh-small` 1.3).
- Accessibilità WCAG 2.1 AA: gerarchia di titoli corretta (un solo H1), alt text su tutte le immagini/loghi,
  contrasto, focus visibile, link esterni riconoscibili (`target="_blank"` con `rel="noopener"` e
  indicazione testuale/icona).
- Performance: immagini dimensionate e lazy load, nessuna libreria JS superflua.
- SEO base: title e meta description della pagina, slug chiaro (es. `/progetto-fondazione-di-sardegna/`),
  Open Graph.
- Privacy: nessun tracciamento o embed aggiuntivo oltre a quanto già presente sul sito; eventuali video
  YouTube in modalità `youtube-nocookie`.
